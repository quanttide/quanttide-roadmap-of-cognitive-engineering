# studio scope

## 范围

思维外脑的交互端——思维收集、澄清对话、知识结构展示。

## 当前状态

- Flutter（android/ios/web/linux）
- 页面基于旧方案（如标注页 annotation_screen），未对齐最新认知模型

## 设计方向（2026-08-22 确认）

**导航 = 4D 认知过程本身**（不发明抽象层，结构即真实）：

```
感知 → 理解 → 预测 → 决策
```

| 导航 | 内容 |
|------|------|
| **感知** | 思维收集输入（想法流、日志）——零门槛，想到就记 |
| **理解** | AI 加工 + 澄清对话（判断清晰度、澄清想法、加工结构化）——AI 加工、人类挑选 |
| **预测** | 认知推演——识别模式（反复出现的想法模式）+ 推演走向（下一步预判/分支） |
| **决策** | 认知判断产出（确立目标、记录决策）——思考云的认知闭环终点 |

## 页面功能（对齐需求地图）

- **感知页**：想法输入 + 想法流时间线（原始想法）；导入素材（来源：quanttide journal）
- **理解页**：判断清晰度（清楚/不清楚）→ 澄清想法（多轮对话）→ 加工结构化（事实/感受/行动）——加工完成即形成情境意识实例（无独立"升级"动作）
- **预测页**：识别模式（AI 识别反复出现的模式）→ 推演走向（趋势 + 分支）
- **决策页**：确立目标（从推演走向中选择一个作为目标——AI 给出候选，用户确认）→ 记录决策（决策时间线 + 与实例关联）

## 实施策略（验证先行——用出来的才算数）

**最小闭环先行：只做 感知 + 理解**

- 收集→判断→澄清→加工→实例——每天都要用的高频路径
- 目标：一周内能真实用起来

**预测/决策延迟**：没有足够的情境意识实例，识别模式/推演走向就是空壳——等实例数据积累后再判断值不值得做

**验证标准**（功能值得做 = 真实使用检验）：

1. **真实使用**：自己用 1-2 周——主动用 / 缺了难受 = 值得做
2. **砍掉验证**：砍掉不受影响 = 不值得做（先问"砍了会不会难受"）
3. **数据驱动**：上线后看每页/每任务使用频率——死功能砍，活功能深化
